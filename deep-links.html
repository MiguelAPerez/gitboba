Deep Links

Last updated: June 30, 2026

GitBoba registers the custom URL scheme gitboba:// and accepts matching Gitea HTTPS links from configured accounts. Use these links on your Gitea instance, in emails, or in internal tools so iOS users can jump straight into the native app.

Self-hosted instances: iOS cannot intercept arbitrary https:// links without per-domain Universal Links setup. The most reliable path today is the Share → Open in GitBoba extension, or explicit gitboba:// buttons in your Gitea templates.

URL scheme

All paths use the gitboba scheme. Owner and repo names are case-sensitive and must match Gitea.

Destination URL format
Repository gitboba://repo/{owner}/{repo}
Pull request gitboba://pull/{owner}/{repo}/{number}
Issue gitboba://issue/{owner}/{repo}/{number}
Commit gitboba://commit/{owner}/{repo}/{sha}
Notifications tab gitboba://notifications

Examples:

gitboba://repo/acme/widget
gitboba://pull/acme/widget/42
gitboba://issue/acme/widget/17
gitboba://commit/acme/widget/a1b2c3d4e5

HTML link (Gitea custom template)

Add an “Open in GitBoba” button anywhere you can inject HTML — a custom footer, custom/extra_tabs.tmpl, or org README. Replace owner, repo, and number with your template variables.

<a href="gitboba://pull/{{.Repository.Owner.Name}}/{{.Repository.Name}}/{{.Issue.Index}}"
   rel="nofollow">
  Open in GitBoba
</a>

For a repository header:

<a href="gitboba://repo/{{.Owner.Name}}/{{.Name}}">
  Open in GitBoba
</a>

JavaScript (derive from the current page)

If your Gitea web URL already matches the patterns below, you can build a deep link from window.location without hard-coding owner/repo:

function gitBobaDeepLink(pathname) {
  const parts = pathname.replace(/^\/+/, '').split('/');
  if (parts.length < 2) return null;

  const [owner, repo, section, id] = parts;
  const base = `gitboba://`;

  if (!section) return `${base}repo/${owner}/${repo}`;
  if (section === 'pulls' && id) return `${base}pull/${owner}/${repo}/${id}`;
  if (section === 'issues' && id) return `${base}issue/${owner}/${repo}/${id}`;
  if (section === 'commit' && id) return `${base}commit/${owner}/${repo}/${id}`;

  return `${base}repo/${owner}/${repo}`;
}

// Example: inject a button on PR pages
const link = gitBobaDeepLink(window.location.pathname);
if (link) {
  const a = document.createElement('a');
  a.href = link;
  a.textContent = 'Open in GitBoba';
  a.className = 'ui button';
  document.querySelector('.issue-title')?.append(a);
}

Supported Gitea web paths: /{owner}/{repo}, /pulls/{n}, /issues/{n}, /commit/{sha}. Subpath installs (e.g. /gitea/owner/repo) are handled automatically when the user has configured the matching base URL in GitBoba.

Safari Smart App Banner

Optional banner in Safari when users visit your Gitea site. Add to your instance’s templates/base/head.tmpl or a custom header injection. Replace YOUR_APP_STORE_ID with GitBoba’s App Store ID (6767851416).

<meta name="apple-itunes-app"
      content="app-id=6767851416, app-argument=gitboba://repo/{{.Owner.Name}}/{{.Name}}">

The app-argument is passed to GitBoba on launch — use any supported deep link for the current page.

Share extension (end users)

Users with GitBoba installed can open any Gitea page from Safari:

  1. Tap Share on a Gitea URL
  2. Choose Open in GitBoba

GitBoba matches the link host against saved accounts, switches to the right instance if needed, and navigates to the repo, PR, issue, or commit.

HTTPS links & Universal Links (advanced)

GitBoba also parses https:// URLs whose host matches a configured account — useful when another app hands off a raw Gitea link via gitboba://open?url=….

Automatic Safari interception (tap link → open app without a custom button) requires Apple Universal Links:

  • Host /.well-known/apple-app-site-association on your Gitea domain
  • Declare the domain in GitBoba’s entitlements (fixed set of hosts per app release)

Because GitBoba users run arbitrary self-hosted domains, Universal Links are documented here for operators who control both the instance and a known domain list — not as the default integration path.

Example AASA snippet (adjust team ID and paths):

{
  "applinks": {
    "apps": [],
    "details": [{
      "appID": "TEAMID.FreeTimeForce.GitBoba",
      "paths": ["/*/pulls/*", "/*/issues/*", "/*/commit/*", "*/*"]
    }]
  }
}

Testing

On a simulator or device with GitBoba installed:

xcrun simctl openurl booted "gitboba://repo/owner/repo"
xcrun simctl openurl booted "gitboba://pull/owner/repo/1"
